================================================================================
PDF TOOLS - FEATURE TRACKER
================================================================================
Scope: the paid PDF feature set of WPS PDF and Adobe Acrobat.
Excluded: every feature that needs an AI API, a language model, or OCR.
          The excluded list is at the bottom.

Status:  [x] = done        [ ] = todo
         A module is only [x] when every line under it is [x].
Level:   E = easy         M = medium         H = hard
         H means a custom engine. It does not mean a model.


================================================================================
DEPENDENCY FLOW - each tier needs the tiers above it
================================================================================

  TIER 1 - CORE ENGINE                    everything below needs this
      - object parser
      - object writer
      - page tree ops
      - content stream + fonts
                        |
                        v
  TIER 2 - PAGE AND FILE LAYER            no text reflow needed
      M1  merge
      M2  split and extract
      M3  page operations
                        |
                        v
  TIER 3 - CONTENT LAYER                  needs a rasteriser + content stream
      M4   convert
      M5   compress
      M6   edit content
      M10  review and compare
                        |
                        v
  TIER 4 - INTERACTIVE OBJECTS + CRYPTO   needs a crypto library
      M7  forms
      M8  sign
      M9  secure


================================================================================
BUILD ORDER
================================================================================
  P1  core engine               parser, writer, page tree   -> M1  M2  M3
  P2  raster + image pipeline   page to image, image to pdf -> M4  M5
  P3  content stream + fonts    the hardest phase           -> M6  M10
  P4  interactive obj writer    AcroForm + appearance       -> M7
  P5  crypto                    security handler, signing   -> M9  M8
  P6  stretch                   PDF to Office, layout only

================================================================================
EXCLUDED - needs a model, an OCR engine, or an API
================================================================================
  These are paid WPS features. They are out of scope for this project.
    -  OCR, scanned PDF to searchable with layout preserved
    -  text edit on a scanned page, depends on OCR
    -  chat with the PDF
    -  summarise a document
    -  translate, layout kept side by side
    -  spell check and grammar
    -  AI rewrite
    -  AI form auto-fill, detect the fields and fill them
    -  explain a selected sentence
    -  smart compression, pick settings per image


================================================================================
NOTES
================================================================================
  -  WPS gives most of this list away free. What it sells is the ceiling of
     each tool: batch, no limits, no watermark, high fidelity.
  -  A text editor that only draws a box on top is not text editing. Rewrite
     the glyph run or the edit is cosmetic.
  -  A redaction that paints black is not a redaction. The bytes must go.
  -  PDF/A is a paid add-on in Acrobat and a checkbox here, because it is
     only a conformance pass over an output we already write.


================================================================================
WHERE TIER 1 ACTUALLY STANDS
================================================================================
  Done and tested:  lexer, object parser, object writer, xref tables, xref
  streams, object streams, incremental updates, broken-offset repair, Flate,
  LZW, ASCIIHex, ASCII85, RunLength, PNG and TIFF predictors, affine
  transforms, the page tree with inheritance, and the content-stream state
  machine with glyph positions.

  189 tests pass, 11 of them against public/sample.pdf, which is a real
  file from a real producer rather than a generated one. The fixtures are written by test/make_fixtures.py, a
  separate Python implementation, and every one is also opened by macOS
  CoreGraphics, so the suite cannot pass by agreeing with the code it tests
  and cannot pass on files that are not real PDFs.

  Added since: per-glyph boxes, so search can highlight the matched
  characters rather than the whole run, and write a correct annotation
  rectangle.

  Not started: object stream generation on write, xref stream on write,
  font program parsing, outline writing, named destinations, encryption.

  Search is done: every occurrence, highlighted in place, with a match
  counter, next and previous, whole-word and match-case options, and
  click-through from the result list. Compare (M10) needs a text diff on
  top of the same boxes, so it is the next thing the state machine gives
  us almost for free.
